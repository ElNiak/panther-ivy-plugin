# IUT Output Analysis Procedure

## When to Use

After `ivy_iut_test` returns a verdict or `panther run` completes an experiment against a real IUT (e.g., FRR for BGP, picoquic for QUIC). This procedure traces failures across three layers: model bugs, serializer bugs, and IUT bugs.

## The 9 Steps

### Step 1: Parse Test Stdout

Read `outputs/<date>/<test>/logs/ivy_tester/stdout.log`. Key patterns:

| Pattern | Meaning |
|---------|---------|
| `> action_name(...)` | Action generated by Ivy solver (sent to IUT) |
| `< action_name(...)` | Action received from IUT |
| `assertion_failed("file.ivy: line N")` | Ivy requirement violation |
| `test_completed` | Clean exit |

### Step 2: Map Assertions to RFC Requirements

For each `assertion_failed` line:
1. Extract `file.ivy: line N`
2. Read the file at that line to find the `require` statement
3. Look for RFC bracket tags (`# [rfc4271:X.Y]`) on or near that line
4. Record: which requirement violated, send or receive side (`_generating` check)

### Step 3: Parse Serializer Debug Output

Read `outputs/<date>/<test>/logs/ivy_tester/stderr.log`. Key patterns:

| Pattern | Meaning |
|---------|---------|
| `bgp_s_wr_len 1` | Serializer `set()` called at state bgp_s_wr_len |
| `ser open_tag path_attr_type = N` | Serializer processing path attribute type N |
| `ser open_list_elem state=N` | Serializer processing array element at state N |
| `ser open_list_elem: unhandled state=N` | State machine gap — element at unexpected state |
| `closing list state=N` | Array boundary at state N |
| `deser_err` | Deserialization failure on received message |

### Step 4: Check IUT Logs

Read `outputs/<date>/<test>/logs/<iut_service>/stderr.log` and `*.log`:
- Protocol-level rejection reasons (e.g., FRR: "Bad message length")
- Connection lifecycle events (accepted, established, closed)
- IUT's perspective on why it rejected the message

### Step 5: Cross-Reference with PCAP

Decode `outputs/<date>/<test>/logs/ivy_tester/ivy_tester.pcap`:

```bash
tshark -Y "bgp" -V -r ivy_tester.pcap          # Full protocol decode
tshark -Y "bgp.type == 2" -V -r ivy_tester.pcap # UPDATE messages only
tshark -T fields -e bgp.type -e bgp.length -r ivy_tester.pcap  # Summary
```

Compare: does the pcap show the message the trace claims was sent? Does Wireshark decode it correctly or show malformed data?

### Step 6: Classify the Failure

| Classification | Indicators |
|---------------|------------|
| **Model bug** | `require` is wrong (too strict/lenient), model generates structurally invalid data |
| **Serializer bug** | `send_bgp_header_message` trace shows correct values but pcap shows wrong bytes |
| **IUT bug** | Model correctly detected RFC non-compliance in IUT response |
| **Unconstrained field** | Z3 generates arbitrary values for a field that should be constrained |

### Step 7: Check Unconstrained Fields

If the IUT reports "invalid value":
1. Check the `around` block for the message event — are all fields constrained?
2. Check the `before` block in the test file — any solver hints missing?
3. Common unconstrained fields: NLRI prefixes, optional parameter values, NOTIFICATION data

### Step 8: Propose Fix Location

| Classification | Fix Location |
|---------------|-------------|
| Model bug | `require` in the relevant `.ivy` stack file |
| Serializer bug | C++ state machine in `{prot}_utils/{prot}_ser_*.ivy` |
| IUT bug | Document as finding; check IUT version |
| Unconstrained field | Add `require` in `around` block or `before` block in test file |

### Step 9: Re-Run and Compare

1. Recompile: `ivy_compile` on the test file
2. Re-run: `panther run` or `ivy_iut_test`
3. Compare: same assertion? Different error? Clean pass?
4. Check pcap: does the wire format now decode correctly?

## Quick Reference: Common Error Codes

### BGP (FRR)

| Error Code | Subcode | Meaning | Likely Cause |
|-----------|---------|---------|-------------|
| 1 (Header) | 1 | Connection Not Synchronized | Marker wrong or TCP framing misaligned (serializer base class leak) |
| 1 (Header) | 2 | Bad Message Length | `header_length` formula wrong in behavior.ivy |
| 3 (UPDATE) | 3 | Missing Well-known Attribute | Required path attribute not included in UPDATE |
| 3 (UPDATE) | 10 | Invalid Network Field | NLRI prefix bytes unconstrained or format wrong |
| 4 | 0 | Hold Timer Expired | Session took too long; timer export competing with generation |
| 6 | 0 | Cease | Normal shutdown (expected in error tests) |

### QUIC

| Error | Meaning | Likely Cause |
|-------|---------|-------------|
| FRAME_ENCODING_ERROR | Frame bytes don't parse | Serializer state machine bug |
| PROTOCOL_VIOLATION | Unexpected frame in context | Model allows frame in wrong connection state |
| FLOW_CONTROL_ERROR | Data exceeds limit | Model doesn't track flow control windows |
